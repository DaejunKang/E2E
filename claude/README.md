# claude/ — E2E 자율주행 개발 문서 세트

이 디렉터리는 **E2E 자율주행 모델 개발 프로젝트의 의사결정 근거와 실행 사양**을 담는다.
Claude Code 세션은 저장소 루트의 `CLAUDE.md`를 먼저 읽고, 필요한 문서를 여기서 참조한다.

---

## 읽는 순서

두 개의 트랙이 있다. 번호는 작성 순서이며, 각 트랙은 **근거 → 방안 → 실행** 순으로 읽는다.

**데이터 자산 트랙**

| 파일 | 역할 | 언제 읽나 |
|---|---|---|
| `01-dataset-inventory.md` | **근거·대장** | 라이선스 원문·데이터셋 사양을 확인할 때 |
| `02-integration-plan.md` | **방안·판단** | 왜 이 아키텍처인지, 무엇을 정규화해야 하는지 |
| `03-asset-buildout-spec.md` | **실행 사양** | 자산을 실제로 구축할 때 |
| `04-py123d-poc-spec.md` | **실행 사양** | py123d 채택 가부를 검증할 때 |

**모델 트랙**

| 파일 | 역할 | 언제 읽나 |
|---|---|---|
| `05-benchmark-sota-survey.md` | **근거 (결과)** | NAVSIM/Bench2Drive 지표 체계와 SOTA 점수를 확인할 때 |
| `06-architecture-recipe-analysis.md` | **방안·판단 (설계)** | 모델 구조·학습 레시피의 유사성·차별성, 1년차 기준 모델 가설 |
| `07-navsim-baseline-run-spec.md` | **실행 사양** | 서버에서 NAVSIM + LTF → DrivoR 학습·평가 loop를 처음 돌릴 때 |

데이터 트랙의 절 참조(`§3의 6개 정규화` 등)는 `02`를, 모델 트랙의 지표 정의는 `05`를 가리킨다.
라이선스 수치와 원문 링크는 전부 `01`에 있다.

## 갱신 주기

| 파일 | 갱신 트리거 |
|---|---|
| `01` | 새 데이터셋 공개, 라이선스·배포 조건 변경 |
| `02` | 통합 전략·아키텍처 판단 변경 |
| `03` | 실행 조건 변경 (스토리지 용량, 용도 등급, 수집 범위) |
| `04` | PoC 진행에 따른 검증 항목 조정 |
| `05` | 리더보드·평가 프로토콜 변경, 신규 SOTA |
| `06` | 신규 모델 분석 추가, 기준 모델 가설 변경 |
| `07` | 실행 결과(`docs/run-report.md`)에 따른 게이트·함정 갱신 |

각 문서 상단에 **최종 갱신일**을 둔다. 파일명에는 날짜를 넣지 않는다.

## 확정 전제 (2026-10-14 기준)

| 항목 | 값 | 출처 |
|---|---|---|

| 평가 지표 | 주 순위 navhard two-stage EPDMS(공식 evaluator), navtest는 evaluator 버전별 분리, PDMS 보조 | `05` §1 |
| 첫 재현 baseline | LTF → DrivoR | `07` |

## 표기 규칙

전 문서 공통.

| 기호 | 의미 |
|---|---|
| ✅ / ✔ | 공식 출처에서 직접 확인 |
| △ | 2차 출처 기반 — 원문 재확인 권장 |
| **(추정)** / **(미검증)** | 작성자 경험칙 또는 확인되지 않은 값 |
| **확인 필요** | 공식 출처를 확보하지 못함. **추정하지 않음** |
| ⚠ | 리스크 · 주의 |

**검증된 값과 추정값을 섞어 쓰지 않는다.** 이 규칙이 무너지면 문서 전체의 신뢰도가 사라진다.
